# الإدارة الإلكترونية للقضايا — تطبيق سطح المكتب

مشروع Electron جاهز بالكامل: مثبّت Windows احترافي (NSIS) + تحديث تلقائي ذكي عبر GitHub Releases + تخزين بيانات محسّن (ملف JSON في مجلد بيانات المستخدم بدل localStorage) + إدارة ملفات القضايا (رفع/فتح/حذف مستندات لكل دعوى).

## 1) ملفات ناقصة لازم تضيفها بنفسك (لأن عندي مفيش إنترنت هنا)
ضع هذه الملفات داخل `src/assets/` بنفس الأسماء (هي نفس الملفات اللي كانت شغالة في نسخة المتصفح):
- `assets/all.min.css` (Font Awesome)
- `assets/xlsx.full.min.js`
- `assets/FileSaver.min.js`

## 2) الأيقونة
حط ملف الأيقونة في `build/icon.ico` (مقاس مفضّل 256×256 بصيغة .ico). لما تبعتلي الصورة، أجهزها لك بصيغة .ico صح وحطها في مكانها.

## 3) قبل أول تشغيل
```bash
npm install
npm start
```

## 4) ربط GitHub للتحديث التلقائي
1. اعمل Repository جديد (خاص Private مفيهاش مشكلة).
2. افتح `package.json` وغيّر:
   ```json
   "publish": [{ "provider": "github", "owner": "اسم_حسابك", "repo": "اسم_الريبو" }]
   ```
3. ارفع المشروع:
   ```bash
   git init
   git add .
   git commit -m "أول نسخة"
   git branch -M main
   git remote add origin https://github.com/اسم_حسابك/اسم_الريبو.git
   git push -u origin main
   ```

## 5) بناء المثبّت ونشر إصدار جديد (تلقائي بالكامل)
كل ما تحدّث الكود وتحب تصدر نسخة جديدة:
```bash
# 1. غيّر رقم الإصدار في package.json مثلاً "1.0.1"
# 2. اعمل commit وpush عادي
git add .
git commit -m "تحديث"
git push

# 3. اعمل تاج بنفس رقم الإصدار وارفعه — ده اللي بيشغّل GitHub Action تلقائيًا
git tag v1.0.1
git push origin v1.0.1
```
GitHub هيبني ملف `.exe` تلقائيًا وينزّله كـ Release جديد. أي مستخدم مثبّت عنده التطبيق، لما يدوس "فحص التحديثات" هيلاقي الإصدار الجديد وينزّله ويثبّته من غير ما يعمل حاجة تانية.

## 6) بناء نسخة على جهازك مباشرة بدون GitHub (اختياري)
```bash
npm run dist
```
هيطلعلك ملف `Setup.exe` جاهز في مجلد `dist/`.

## بنية المشروع
```
main.js         العملية الرئيسية (تخزين البيانات + إدارة الملفات + التحديث)
preload.js      الجسر الآمن بين main.js والواجهة
src/index.html  واجهة التطبيق (نفس ملفك بدون أي تعديل في المنطق)
build/icon.ico  أيقونة التطبيق (لازم تضيفها)
.github/workflows/release.yml   بناء ونشر تلقائي عبر GitHub Actions
```

## ملاحظات مهمة
- البيانات بتتخزن في: `%APPDATA%/الإدارة الإلكترونية للقضايا/data.json`
- ملفات القضايا بتتخزن في: `%APPDATA%/الإدارة الإلكترونية للقضايا/CaseFiles/اسم_المدعي_رقم_الدعوى/نوع_المستند/`
- التطبيق بيتحقق من التحديثات فقط لما تدوس زرار "فحص التحديثات" (مفيش فحص تلقائي في الخلفية دلوقتي — لو تحبه يبقى تلقائي كل ما يفتح التطبيق، قولي وأضيفه).
